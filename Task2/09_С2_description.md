
# Краткое описание

---

- Добавлен сценарий просмотра истории покупок.
- Добавлен отдельный `Order History Query Service`, который подписывается на события и хранит готовую read-модель для экранов списка и деталей заказа.

---

# Read-модель истории заказов

`Order History Query Service` хранит данные, которые нужны мобильному приложению без дополнительных синхронных вызовов в доменные сервисы.

---

| Свойство | Как достигается |
| --- | --- |
| Быстрый отклик | Один запрос к read-сервису вместо API Composition по нескольким сервисам. Read DB индексируется по `buyerId`, `createdAt` и `orderId`. |
| Корректная история | В заказе хранится снимок названий, количества и цен на момент покупки; изменения каталога не переписывают прошлые покупки. |
| Масштабирование чтения | `Order History Query Service` можно масштабировать отдельно от write-сервисов и вынести read DB в реплики. |
| Допустимая задержка обновления | История является eventually consistent; после нового события read-модель обновляется асинхронно. |
| Надежная доставка событий | Обработчики используют inbox/idempotency и сох

---

| Поле read-модели | Источник |
| --- | --- |
| `orderId`, `buyerId`, `createdAt`, `finalStatus` | `OrderCreated`, `OrderPaid`, `OrderCancelled`, `ShipmentStatusChanged` |
| Состав заказа: `productId`, название, количество, цена на момент покупки | `OrderCreated` с immutable-снимком строк заказа |
| Итоговая сумма, способ оплаты, `paymentId` | `PaymentSucceeded`, `PaymentFailed`, `RefundSucceeded` |
| Способ доставки, адрес, ETA, трек-номер | `DeliveryCreated`, `ShipmentStatusChanged` |
| `receiptId` или `receiptUrl` | `ReceiptIssued` |
| Доступность действий `downloadReceipt`, `leaveReview`, `orderAgain` | Рассчитывается read-сервисом по статусу заказа, наличию нужных идентификаторов и событиям `ReviewCreated` |

## Поток чтения и команд

| Действие пользователя | Маршрут | Поведение |
| --- | --- | --- |
| Открыть список покупок | `GET /me/order-history` | API Gateway обращается только к `Order History Query Service`; ответ содержит краткие карточки заказов. |
| Открыть детали заказа | `GET /me/order-history/{orderId}` | Read-сервис возвращает состав, суммы, доставку, оплату, финальный статус и доступные действия. |
| Скачать чек | `GET /payments/{paymentId}/receipt` | Gateway маршрутизирует запрос в `Payment Service`, который проверяет владельца и отдает чек или ссылку. |
| Оставить отзыв | `POST /products/{productId}/reviews` | Команда идет в `Review Service`; после публикации `ReviewCreated` рейтинг обновится асинхронно. |
| Заказать снова | `POST /cart/reorder` | Команда идет в `Cart Service`; текущие цены и наличие будут проверены заново при оформлении нового заказа. |
